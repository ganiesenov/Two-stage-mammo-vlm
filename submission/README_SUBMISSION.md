## Как собираются чистая и подсвеченная версии

Обе — **из одного исходника**. `manuscript/main.tex` содержит флаг:

```latex
\ifdefined\MARKUPVERSION \markuptrue \else \markupfalse \fi
```

`main_marked.tex` — сгенерированная полная копия `main.tex` с включённым флагом.
Генерируется скриптом, руками не правится:

```
python scripts/7_revision/20_make_marked.py
```

Любая правка вносится в `main.tex`, после чего скрипт запускается заново — иначе
подсвеченная версия разойдётся с чистой.

### Подсвеченная версия собирается в Overleaf (pdfLaTeX)

Правки этого раунда отмечены **полосой на поле** (пакет `changebar`, цвет
`markerbar`). Локальный tectonic использует XeTeX и полосы не рисует — подсвеченная
версия выйдет визуально неотличимой от чистой. Поэтому **файл 3 собирается только
в Overleaf**, и перед заливкой глазами проверяется, что полосы видны и оранжевые.

Запасной режим на случай сборки движком без поддержки changebar: в преамбуле
`\markbartrue` → `\markbarfalse`, правки станут синим текстом. **При переключении
обязательно переписать шапку MARKED-UP COPY**: её текст обещает «bar in the outer
margin», с синим текстом это будет неверно. Шапка уже содержит обе ветки под
`\ifmarkbar`, менять нужно только флаг — но проверить вывод.

## Разметка правок

Подсвечена **только дельта второго раунда**. Разметка первого раунда снята скриптом
`scripts/7_revision/24_reset_markup.py`: `\rev{X}` → `X`, `\del{...}` и `\delpar{...}`
удалены вместе с содержимым. Правки первого раунда стали обычным текстом статьи.

Макросы: `\rev` (текст), `\revm` (формулы), `\revf` / `\revmf` (внутри таблиц и подписей,
там полоса на поле недоступна и используется цвет), `\todo` (печатается в обеих версиях
красным как защита от подачи с незаполненными данными; сейчас таких меток нет).

## Архив Zenodo: порядок, ломающий круг «DOI ↔ архив»

Ответ рецензентам утверждает, что скрипты и по-сэмпловые генерации лежат в released
archive, а Code Availability указывает DOI версии. Архив на Zenodo — версии первого
раунда, поэтому оба утверждения станут правдой только после публикации новой версии.
Порядок обязателен именно такой:

1. На Zenodo создать draft новой версии существующей записи и нажать **Reserve DOI** —
   version DOI выдаётся до публикации.
2. Вписать зарезервированный DOI в Code Availability `manuscript/main.tex`
   (concept DOI `10.5281/zenodo.21850474` не меняется).
3. Коммит всего дерева.
4. Собрать архив **с этого коммита**, залить в draft, опубликовать версию.

Так DOI в тексте и на Zenodo сходятся без второго круга правок.

Грепом по тексту PDF **должно быть пусто**:
`original submission`, `original version`, `previously reported`, `withdrawn`,
`has been redrawn`, `[REMOVED`, `EDITORIAL`, `delete before`, `TODO`, `??`,
`40 training runs`, `four of nine`, `\kappa = 0.17`.

Грепом **должно находиться** — в обеих версиях, чистой и подсвеченной:
* подсекция `Use of generative AI` в конце Methods;
* новый version DOI в Code Availability (и concept DOI `...474` рядом).

Легальные исключения, которые греп по старым числам всё же поймает:
* тестовая колонка Table 8 (0.671 / 0.685 / 0.729) — она на полном сплите из 52
  изображений, потому что per-sample генерации сохранены только для двух из семи
  конфигураций; оговорено в подписи;
* абзац sensitivity после Table 5 — там числа полного сплита приводятся намеренно;
* Table 3 (Stage 1, синтетика) — отдельный эксперимент, n=30, не менялся;
* строки baseline в Table 4, помеченные ‡, и строка AMRG.
